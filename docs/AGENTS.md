# Documentation guidance

## Versioned documentation

Migration prompts may compare V1 and V2 to explain the work that needs to be
done. Treat those comparisons as internal context, not published documentation.

Write V2 documentation as standalone product documentation. Describe the
current API, behavior, and workflow directly. Do not frame features in terms of
V1, use labels such as "V2 API" or "new API," or explain what changed unless the
page is specifically a migration guide or changelog.

Mention a version only when readers need it to complete the task, such as a
package dist-tag, runtime requirement, compatibility constraint, or versioned
URL.
