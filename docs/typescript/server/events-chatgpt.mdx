ChatGPT subscribes to MCP Events through webhooks in the `openai` dialect.
When an event arrives, ChatGPT runs an event-triggered scheduled task and
decides what to do from the event's `description`. mcp-use detects ChatGPT
and answers in its dialect automatically.

## Meet the prerequisites

- A ChatGPT workspace plan with **Developer mode** enabled.
- **Allow event-triggered scheduled tasks** enabled in the workspace settings.
- A server reachable over HTTPS. In development, use `mcp-use dev --tunnel`.

## Connect through a tunnel

```sh
mcp-use dev --tunnel
```

Add the printed `https://…/mcp` URL as a connector in ChatGPT. A server with
no OAuth accepts anonymous `openai` webhook subscriptions
(`events.anonymous: "auto"`), so no sign-in is needed to try it. Tunnel URLs
change between sessions; add the connector again when the URL changes.

## Refresh tools after catalog changes

ChatGPT caches the event catalog with the tool list. After you add, rename or
change an event, open the connector and press **Refresh tools**. Without a
refresh, ChatGPT shows "no available webhook events" or keeps the old schema.

## Request the event scopes

ChatGPT requests the scopes it sees on tools at sign-in. If your events need
scopes that no tool declares, subscribe fails with `insufficient_scope`. Fix
it with one option:

```ts
const server = new MCPServer({
  name: "issues",
  version: "1.0.0",
  oauth: oauthClerkProvider(),
  events: { scopes: { attachToTools: true } },
});
```

`attachToTools` adds the union of event scopes to every tool's
`securitySchemes`.

## Write descriptions ChatGPT can act on

ChatGPT's default reaction is to notify the user only. It reads nothing but
the `description` to choose another reaction.

```ts
description:
  "A new issue was opened in a GitHub repository you can access. Summarize it and suggest labels.",
```

- State the trigger and the action in one or two sentences.
- Keep payloads small: ids, URLs and summaries.
- Never put instructions in the payload; it is untrusted data.

## Add a read tool for missing data

Some ChatGPT surfaces (the "dots" notification view) show the event without
its payload. Give the model a tool that reads the latest occurrences, and
mention it in the description:

```ts
server.tool(
  { name: "get_note", inputSchema: z.object({ noteId: z.string() }) },
  async ({ noteId }) => ({ content: [{ type: "text", text: JSON.stringify(notes.get(noteId)) }] })
);

server.event({
  name: "note.created",
  description: "A note was created. Call get_note with noteId to read it, then summarize it.",
  // …
});
```

## Expect pause and resume

When a user pauses the scheduled task, ChatGPT stops refreshing the
subscription. mcp-use keeps the subscription until its TTL (24 hours by
default) expires, then runs `onUnsubscribe(sub, "expired")`. Deliveries that
fail while ChatGPT is unavailable retry for 15 minutes, then go to dead
letters you can redeliver from the Inspector or `mcp-use events`.

## Check host support

| Host | Dialect | Modes |
|---|---|---|
| ChatGPT (web, Developer mode) | `openai` | webhook |
| ChatGPT mobile and desktop | `openai` | webhook, once the task is created on web |

## Verify the integration

1. Run `mcp-use dev --tunnel` and add the connector in ChatGPT.
2. Ask ChatGPT to create a task "when a note is created in inbox".
3. Confirm the subscription in the Inspector's **Events** tab, server subscriptions panel.
4. Call `create_note` with `{ "folder": "inbox" }` from the Inspector.
5. Confirm the delivery shows `2xx` and the task runs in ChatGPT.
6. Change the event description, press **Refresh tools**, and repeat step 4.
