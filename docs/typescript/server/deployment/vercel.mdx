---
title: Vercel Functions
description: Deploy an mcp-use server with Views as a Vercel Function.
---

For a non-Next Vercel Function, build locally, use a JavaScript function entry
that imports the generated server, include `.mcp-use/build/views/**` in the
function bundle, and rewrite nested asset paths to that entry.

```js api/mcp.js
import server from "../.mcp-use/build/index.js";

export default server;
```

```json vercel.json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "buildCommand": "echo 'Using prebuilt .mcp-use artifacts'",
  "functions": {
    "api/mcp.js": {
      "includeFiles": ".mcp-use/build/views/**"
    }
  },
  "rewrites": [
    {
      "source": "/api/mcp/:path*",
      "destination": "/api/mcp"
    }
  ]
}
```

The scaffold ignores `.mcp-use/` from Git, so add a `.vercelignore` that does
not exclude the generated build:

```text .vercelignore
node_modules
.vercel
```

```bash
MCP_URL=https://<project>.vercel.app npm run build
vercel --prod
```

Configure `basePath: "/api/mcp"` so the SDK derives the full endpoint from
the public origin, then verify the rendered resource:

```bash
npx --yes mcp-use@beta screenshot \
  --mcp https://<project>.vercel.app/api/mcp --tool show-app \
  --output vercel-live-view.png
```

For Next.js, keep using the specialized `withMcpUse()` and
`createNextHandler()` integration described in the [Next.js guide](/typescript/server/nextjs-drop-in).
