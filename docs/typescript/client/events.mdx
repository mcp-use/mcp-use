The mcp-use client consumes MCP Events from any server that speaks
SEP-3415 or the ChatGPT dialect. The manager picks a delivery mode, persists
cursors, dedupes, and resumes after restarts.

## Subscribe with the manager

```ts
import { MCPClient } from "mcp-use";

const client = new MCPClient(
  { mcpServers: { notes: { url: "https://notes.example.com/mcp" } } },
  {
    events: { store: fileEventsStore(".mcp-use/client-events") },
    onEventsError: (err) => console.error(err.code, err.message),
  }
);

const sub = await client.events.subscribe("notes", "note.created", { folder: "inbox" });
for await (const event of sub) {
  console.log(event.data); // untrusted
}
```

Without a receiver the manager uses push, then poll. `sub.cursor` is
persisted after each event, so the next session resumes where this one
stopped.

| Member | Meaning |
|---|---|
| `sub.mode` | `webhook`, `push` or `poll` |
| `sub.id` | Webhook subscription id, or the direct id for poll and push |
| `sub.close()` | Stop locally and keep the record for resume |
| `sub.cancel()` | Unsubscribe and forget the record |
| `client.events.list("notes")` | The server's event descriptors |
| `client.events.subscriptions()` | Persisted `ClientSubscriptionRecord`s |

## Choose a mode

```ts
events: {
  receiver: { url: "https://app.example.com/api/mcp-events" },
  prefer: ["webhook", "push", "poll"],
}
```

The first entry of `prefer` the server lists for the event wins. Against a
ChatGPT-dialect server (webhook only) with no receiver, subscribe throws
`receiver_required`. Force one with `{ mode: "poll" }`.

| Runner | Needs | Notes |
|---|---|---|
| Push | A streaming connection | Reconnects with the cursor; rotates at the server's maximum duration |
| Poll | Replayable event | Honors the server's `nextPollMs` |
| Webhook | A public receiver URL | Refreshes before expiry; rotates secrets |

## Receive webhooks

```ts title="app/api/mcp-events/route.ts"
export const POST = client.events.createWebhookHandler();
```

The handler verifies signatures, answers verification challenges, dedupes and
dispatches to `onEvent`. For a standalone receiver without the manager, use
`createWebhookHandler` from `@mcp-use/client/webhooks` with your own
`resolve` and `onEvent`; it returns `2xx` only after `onEvent` resolves.
Mount it where nothing pre-parses the body.

In development, receive locally through a tunnel:

```ts
events: { receiver: { listen: { port: 8787, tunnel: true } } }
```

## Handle gaps and termination

```ts
const sub = await client.events.subscribe("notes", "note.created", {}, {
  onGap: () => refetchNotes(),            // retention skipped events
  onTerminated: (t) => console.warn(t),   // the server revoked the subscription
});
```

## Persist and resume

| Store | Runtime |
|---|---|
| `memoryEventsStore()` | Default in Node |
| `fileEventsStore(dir)` | Node, atomic writes |
| `localStorageEventsStore()` | Browsers |

With `resume: "auto"` (default), persisted subscriptions restart when a
session for their server opens. Each record keeps the last 64 event ids, so
dedupe survives restarts.

## Type subscriptions from server code

```ts
import type { noteCreated } from "../server/index";
const sub = await client.events.subscribe<typeof noteCreated>("notes", "note.created", { folder: "inbox" });
// event.data is { folder: string; noteId: string; title: string }
```

## Use events in React

```tsx
import { useMcp, useMcpEvent } from "mcp-use/react";

function Inbox() {
  const mcp = useMcp({ url: "https://notes.example.com/mcp" });
  useMcpEvent(mcp, "note.created", { folder: "inbox" }, (e) => toast(e.data.title));
  return <ul>{mcp.receivedEvents?.map((e) => <li key={e.eventId}>{e.name}</li>)}</ul>;
}
```

- `mcp.events` lists descriptors; `mcp.eventsSupported` reports the capability.
- `mode: "auto"` tries push, then poll, then webhook. Webhook-only servers need `receiverUrl`.
- `keep: true` closes on unmount and resumes on remount; the default cancels.
- Cursors persist in `localStorage`, so reloads resume.
- On HTTP/1.1, at most 4 streams per server run at once; further subscriptions poll.

## Use the lower layers

| Layer | API |
|---|---|
| Capability sniffing | `connection` capabilities expose whether the server supports Events |
| Connection calls | `pollEvents`, `streamEvents`, `subscribeEvent`, `unsubscribeEvent` |
| Webhook primitives | `verifyWebhook`, `generateWebhookSecret` from `@mcp-use/client/webhooks` |

Use these only when the manager does not fit.

See the maintained receiver in
[`examples/mcp-events-receiver`](https://github.com/mcp-use/mcp-use/tree/main/libraries/typescript/packages/server/examples/mcp-events-receiver).
