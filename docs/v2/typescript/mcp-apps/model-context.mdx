Use model context to give the next model turn the information it needs.
Tool results establish the initial context.
`useViewState` and `ModelContext` describe the view.
`useModelContext` manages selected native attachments.
Keep each piece of evidence in one context channel.

## Choose the right channel

| Need                                          | Use                                                            |
| --------------------------------------------- | -------------------------------------------------------------- |
| Return a concise tool result                  | A text `content` block                                         |
| Send structured render data to the view       | Tool-result `structuredContent`, read through `useToolContext` |
| Keep structured user choices model-visible    | `useViewState`                                                 |
| Attach selected text, images, or resources    | `useModelContext`                                              |
| Describe what the user currently sees         | `<ModelContext>`                                               |
| Keep ephemeral UI state private to the iframe | React `useState`                                               |
| Persist durable business data                 | Your backend                                                   |

## Attach evidence to the next turn

Use `useModelContext()` to add selected text, images, resource links, or embedded resources to the next model turn.
The hook shares one attachment collection across the view.
You can add, replace, remove, and clear attachments with stable application keys.

Read [Attach evidence with ChatGPT Extensions](/v2/typescript/mcp-apps/chatgpt-extensions#attach-evidence-to-the-next-model-turn) for complete examples, image inputs, and error handling.
The guide also explains host removals and how to combine the hook with `useViewState` and `ModelContext`.

## Keep structured choices in view state

Use `useViewState` for selections, filters, drafts, and progress that future model turns should understand.

```tsx
import { useViewState } from "mcp-use/react";

function Filters() {
  const [state, setState] = useViewState({
    selectedCategory: "all",
    sort: "newest",
  });

  return (
    <button onClick={() => setState({ ...state, sort: "price" })}>
      Sort by price
    </button>
  );
}
```

The root state value must be a JSON-serializable object.
All components in one mounted view share it.
Separate view instances remain isolated.

By default, ChatGPT restores state through `window.openai.widgetState`.
Other MCP Apps hosts keep state for the current iframe lifetime.
After `useModelContext` activates native delivery, OpenAI host context can restore model-visible state and attachments.
Private UI persistence remains separate.

## Describe visible UI

Use `ModelContext` for natural-language descriptions that follow the React component lifecycle.

```tsx
import { ModelContext } from "mcp-use/react";

function Dashboard() {
  return (
    <ModelContext content="Dashboard">
      <ModelContext content="Revenue chart is visible" />
      <ModelContext content="Three alerts are unresolved" />
    </ModelContext>
  );
}
```

Nested components serialize into an indented tree:

```text
- Dashboard
  - Revenue chart is visible
  - Three alerts are unresolved
```

For descriptions from event handlers or other callbacks, store the description in React state and render it with `ModelContext`:

```tsx
import { useState } from "react";
import { ModelContext } from "mcp-use/react";

function ProductPicker() {
  const [selection, setSelection] = useState<string | null>(null);

  return (
    <>
      {selection && <ModelContext content={`Selected ${selection}`} />}
      <button onClick={() => setSelection("Wireless Headphones")}>
        Select headphones
      </button>
    </>
  );
}
```

## Understand the merged snapshot

The runtime merges structured state and the serialized context tree into one complete object:

```json
{
  "selectedCategory": "audio",
  "sort": "price",
  "_uiContext": "- Dashboard\n  - Revenue chart is visible"
}
```

`_uiContext` is a reserved model-visible field.
`useViewState` filters it from application state and rejects developer state with the same key.

Every write sends the complete snapshot.
On MCP Apps hosts, mcp-use sends the object as `structuredContent` and a JSON text block as `content` through `ui/update-model-context`.
On ChatGPT, views without `useModelContext` write the object to `modelContent` with `window.openai.setWidgetState`.
Views with `useModelContext` use the shared native writer described in [ChatGPT Extensions](/v2/typescript/mcp-apps/chatgpt-extensions#combine-context-hooks).

## Keep ephemeral values local

Use React `useState` for transient details that the model does not need, such as hover state, open tooltips, or animation progress.

```tsx
import { useState } from "react";

function HoverPreview() {
  const [hoveredId, setHoveredId] = useState<string | null>(null);

  return (
    <button
      onMouseEnter={() => setHoveredId("book:cover")}
      onMouseLeave={() => setHoveredId(null)}
    >
      {hoveredId ? "Show cover preview" : "Preview cover"}
    </button>
  );
}
```
