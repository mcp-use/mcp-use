Use MCP middleware when logic depends on a parsed MCP operation. Use Hono
middleware for HTTP concerns that run before MCP parsing.

| Need                                                 | Layer           |
| ---------------------------------------------------- | --------------- |
| Inspect a tool name or transform a list result       | MCP middleware  |
| Enforce scopes for an MCP operation                  | MCP middleware  |
| Add CORS, headers, request logging, or custom routes | Hono middleware |

Both layers are request-scoped. Client metadata is carried on each request and
there is no session affinity between calls.

## Wrap an MCP operation

```typescript
import { MCPServer } from "mcp-use";
import { z } from "zod";

const server = new MCPServer({
  name: "middleware-server",
  version: "1.0.0",
});

server.use("mcp:tools/call", async (ctx, next) => {
  const startedAt = Date.now();
  const result = await next();
  console.log(`${ctx.params.name}: ${Date.now() - startedAt}ms`);
  return result;
});

server.tool(
  {
    name: "echo",
    inputSchema: z.object({ message: z.string() }),
  },
  async ({ message }) => ({
    content: [{ type: "text", text: message }],
  }),
);

export default server;
```

Exact patterns currently include:

- `mcp:tools/call` and `mcp:tools/list`
- `mcp:resources/read` and `mcp:resources/list`
- `mcp:prompts/get` and `mcp:prompts/list`

Exact middleware may inspect or replace its method-specific result. The
`mcp:*` wildcard is a pass-through wrapper: call `next()` or throw, and do not
replace the downstream result. Middleware does not wrap initialization,
completion, log-level changes, or subscription listen requests.

## Read the originating HTTP request

`ctx.request` is the originating Hono `HonoRequest` when the MCP operation came
from HTTP. Read headers with `ctx.request.header(name)`, the path with
`ctx.request.path`, and the underlying Web `Request` with
`ctx.request.raw`.

```typescript
server.use("mcp:tools/list", async (ctx, next) => {
  console.log(ctx.request?.header("user-agent"));
  return next();
});
```

Values set by Hono middleware with `c.set()` are available through `ctx.get()`.

## Authorize and rate-limit verified identities

When OAuth is configured, middleware `ctx.auth` contains verified SDK auth
information. This example limits each verified OAuth client:

```typescript
import { MCPServer } from "mcp-use";
import { oauthAuth0Provider } from "mcp-use/oauth/auth0";

const domain = process.env.AUTH0_DOMAIN;
if (!domain) throw new Error("AUTH0_DOMAIN is required");

const authenticatedServer = new MCPServer({
  name: "rate-limited-server",
  version: "1.0.0",
  oauth: oauthAuth0Provider({ domain }),
});

authenticatedServer.use("mcp:tools/call", async (ctx, next) => {
  const key = ctx.auth.clientId;
  if (!key) {
    throw new Error("A verified OAuth client identity is required.");
  }

  if (!(await rateLimiter.take(`oauth-client:${key}`, 30, "1m"))) {
    throw new Error("Rate limit exceeded.");
  }

  return next();
});
```

Use a provider-mapped user subject or a trusted gateway identity when the
limit must be per end user. Never key access control or rate limiting by a
transport session ID, self-reported client metadata, or an unverified header.
Use a shared external store for distributed limits.

## Filter discovery

List middleware receives the item array rather than the protocol envelope:

```typescript
server.use("mcp:tools/list", async (_ctx, next) => {
  const tools = await next();
  return tools.filter((tool) => !tool.name.startsWith("_"));
});
```

Register middleware in deliberate order. The first registered handler is the
outermost wrapper.

## Add Hono middleware

Register ordinary Hono middleware without the `mcp:` prefix:

```typescript
server.use("*", async (c, next) => {
  const startedAt = Date.now();
  c.header("x-server", "mcp-use");
  await next();
  console.log(`${c.req.method} ${c.req.path}: ${Date.now() - startedAt}ms`);
});

server.get("/health", (c) => c.json({ ok: true }));
```

Use Hono middleware for raw HTTP policy and MCP middleware for parsed operation
policy.
