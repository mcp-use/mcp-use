Use the mcp-use TypeScript server framework to build stateless MCP servers with tools, resources, prompts, authentication, or interactive MCP App Views.

If you are starting from scratch, use the [TypeScript quickstart](/v2/typescript/getting-started/quickstart) to scaffold a server. Use [Build your first MCP App](/v2/typescript/mcp-apps/quickstart) when the server should return a React View.

## What mcp-use adds

- **One-command scaffolding:** `npx create-mcp-use-app@beta` creates a runnable server with scripts, TypeScript configuration, examples, and optional Views.
- **Inspector-first development:** `npm run dev` serves the MCP endpoint and Inspector so you can test tools, resources, prompts, and Views locally.
- **Hot reload:** tools, resources, prompts, and Views update without manually restarting the development server.
- **Bring your own validation library:** tool inputs, tool outputs, and prompt arguments accept Standard Schema-compatible validators with JSON Schema conversion.
- **MCP Apps support:** create interactive Views that run in Claude and ChatGPT.
- **Web-standard runtime:** run the same stateless server with the CLI, Hono, Fetch, Next.js, or a supported serverless platform.

Zod, ArkType, and Valibot implement the required Standard Schema interfaces. The generated project uses Zod, but you can use another compatible validation library without changing the mcp-use registration API.

## Core server concepts

### Server instance

Create one `MCPServer` instance in your entry file. It owns MCP registrations, the Hono application, Web-standard request handling, authentication, and development routes.

```typescript
import { MCPServer } from "mcp-use";

const server = new MCPServer({
  name: "inventory-server",
  title: "Inventory Server",
  version: "1.0.0",
  description: "Look up products and prepare inventory summaries",
  instructions:
    "Call search-products before get-product-details. Confirm availability before preparing an order.",
});
```

`instructions` are returned during MCP initialization. Use them for server-wide workflow guidance that does not belong in a single tool description.

The CLI entry should default-export the server after registering its tools, resources, and prompts. The CLI then owns the HTTP listener.

```typescript
export default server;
```

For a standalone Node.js script, call `await server.listen()` instead.

### Tools

Tools are functions clients can invoke. Use tools for actions, lookups, and workflows.

```typescript
import { z } from "zod";

export const getTime = server.tool(
  {
    name: "get-time",
    description: "Return the current server time as an ISO timestamp",
    inputSchema: z.object({}),
    annotations: {
      readOnlyHint: true,
      destructiveHint: false,
      openWorldHint: false,
    },
  },
  async () => ({
    content: [{ type: "text", text: new Date().toISOString() }],
  }),
);
```

`inputSchema` and `outputSchema` accept any compatible Standard Schema validator. Zod is used here because it is the default in generated projects.

Learn more in [Tools](/v2/typescript/server/tools).

### Resources

Resources expose readable content by URI. Use resources for configuration, documents, generated data, or files that clients should inspect.

```typescript
server.resource(
  {
    name: "inventory-summary",
    uri: "inventory://summary",
    title: "Inventory Summary",
    description: "Current warehouse inventory totals",
    mimeType: "application/json",
  },
  async (uri) => ({
    contents: [
      {
        uri: uri.href,
        mimeType: "application/json",
        text: JSON.stringify({
          warehouses: 3,
          products: 1284,
          lowStockItems: 17,
        }),
      },
    ],
  }),
);
```

Learn more in [Resources](/v2/typescript/server/resources).

### Prompts

Prompts are reusable templates for model interactions. Use prompts when clients should reuse a structured instruction with validated arguments.

```typescript
server.prompt(
  {
    name: "summarize-inventory",
    description: "Create an inventory summary for a specific audience",
    schema: z.object({
      audience: z.enum(["operations", "finance", "support"]),
      timeframe: z.string().describe("Reporting period, such as today or Q2"),
    }),
  },
  async ({ audience, timeframe }) => ({
    messages: [
      {
        role: "user",
        content: {
          type: "text",
          text: `Summarize inventory changes for ${audience} during ${timeframe}. Include risks, causes, and next actions.`,
        },
      },
    ],
  }),
);
```

Learn more in [Prompts](/v2/typescript/server/prompts).

### MCP Apps

An MCP App View is a React component rendered from a tool result. Put the component in `views/<view-name>/view.tsx`, then bind it to a tool with `view: { name }`.

A View-bound tool must declare an `outputSchema` and return matching `structuredContent`. Export the tool reference so `mcp-env.d.ts` can provide typed data to the View.

```typescript
export const searchProducts = server.tool(
  {
    name: "search-products",
    description: "Search products and display the results in a View",
    inputSchema: z.object({
      query: z.string().describe("Search term"),
    }),
    outputSchema: z.object({
      query: z.string(),
      results: z.array(z.object({ id: z.string(), name: z.string() })),
    }),
    annotations: {
      readOnlyHint: true,
      destructiveHint: false,
      openWorldHint: true,
    },
    view: {
      name: "product-search-result",
      description: "Product search results",
    },
  },
  async ({ query }) => {
    const results = await catalog.searchProducts(query);
    const data = { query, results };

    return {
      content: [
        {
          type: "text",
          text: `Found ${results.length} products for "${query}"`,
        },
      ],
      structuredContent: data,
    };
  },
);
```

The View reads the typed tool result with `useToolContext()`.

```tsx
// views/product-search-result/view.tsx
import { useToolContext } from "mcp-use/react";

export default function ProductSearchResult() {
  const view = useToolContext<"search-products">();

  if (view.status === "pending") {
    return <div className="p-4">Searching…</div>;
  }

  if (view.status === "error") {
    return <div className="p-4">{view.error.message}</div>;
  }

  const { query, results } = view.toolOutput;

  return (
    <div className="p-4">
      <h3>Results for "{query}"</h3>
      <ul>
        {results.map((result) => (
          <li key={result.id}>{result.name}</li>
        ))}
      </ul>
    </div>
  );
}
```

Learn more in [MCP Apps](/v2/typescript/mcp-apps) and [Build your first MCP App](/v2/typescript/mcp-apps/quickstart).

## Local development loop

Run the development server from a scaffolded project:

```bash
npm run dev
```

By default, local development gives you:

| URL                                      | Purpose                                                       |
| ---------------------------------------- | ------------------------------------------------------------- |
| `http://localhost:3000/mcp`              | MCP endpoint for clients.                                     |
| `http://localhost:3000/mcp/inspector`    | Inspector for testing tools, resources, prompts, and Views.   |

Keep the Inspector open while editing `index.ts` and files under `views/`. The development server reloads MCP registrations and View assets as they change.
