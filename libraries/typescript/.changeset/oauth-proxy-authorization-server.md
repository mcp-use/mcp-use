Add `oauthProxy()` to `mcp-use/oauth`: the MCP server becomes its own OAuth authorization server in front of an identity provider without dynamic client registration, such as GitHub (`github()`) or Google (`google()`), or any OAuth 2.0 provider (`upstream()`). Clients present a client ID metadata document or register (DCR), approve a consent page the server owns (it names the server by its `title`, then its `name`; `resourceName` overrides both), and receive the proxy's own opaque tokens. The `clients` option limits which clients may connect, by metadata document URL or origin, or by a client defined on the server. The upstream client secret and tokens stay on the server, encrypted in a shared store (`mcp-use/oauth/storage`: Upstash, Redis, Postgres, Firestore, Cloudflare D1 or Durable Object, and an in-memory store for local development). `redisStorage` takes a connected client or a function that connects one on first use. Tools read the upstream token with `upstreamToken(ctx)` or `ctx.auth.upstream`. When a sign-in or refresh fails, the server log names the cause without token or code values: the provider's own error code and description, the HTTP status and content type, an `iss` that names another issuer, or the network error. The client's `error_description` names the provider's error code. The log also reports refused client metadata documents and stored records encrypted with a secret the server no longer has. Inside `mcp-use build`, where `isBuilding()` is true, `oauthProxy` requires no secret, store, or upstream client credentials, and `upstashStorage` requires no URL or token.

`firebase()` signs users in with Firebase Authentication, which has no OAuth authorization endpoint. Clicking Allow on the consent page opens the Firebase sign-in popup (Firebase JS SDK 12.19.0 from `www.gstatic.com`), and the page posts the user's ID token and refresh token with the decision. The proxy checks the token's signature, project, issuer, sign-in provider, sign-in time (`maxAuthAge`, 5 minutes by default), tenant, and optionally a verified email, and refreshes the ID token on the server through the Token Service API; a refresh that Firebase refuses for good ends every grant of the user. Tools get the Firebase ID token from `upstreamToken(ctx)`. The `emulator` option accepts the Firebase Auth emulator's unsigned tokens, and only for a server on localhost: a localhost resource URL and, under `listen()`, a loopback bind. Custom in-page upstreams implement `InPageUpstream`, and their `refresh` throws `UpstreamRefreshError` to report a revoked sign-in.

OAuth providers can now register public HTTP routes from `setup()` with `host.route()`, read the mount mode as `host.mode`, the `listen()` bind address as `host.listenHost`, and the server's `name` and `title` as `host.serverInfo`, and compute `oauthMetadata` from the resolved resource URL. OAuth endpoints under the MCP path are never written to trace logs, and `oauthEnvironmentValue` no longer throws on runtimes without `process`.
