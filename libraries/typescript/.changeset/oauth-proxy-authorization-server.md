Add `oauthProxy()` to `mcp-use/oauth`: the MCP server becomes its own OAuth authorization server in front of an identity provider without dynamic client registration, such as GitHub (`github()`) or Google (`google()`), or any OAuth 2.0 provider (`upstream()`). Clients present a client ID metadata document or register (DCR), approve a consent page the server owns (it names the server by the host of its URL, for example `mcp.acme.com`), and receive the proxy's own opaque tokens. The `clients` option limits which clients may connect, by metadata document URL or origin, or by a client defined on the server. The upstream client secret and the user's upstream tokens stay on the server, and the tokens and other proxy records are stored encrypted in a shared store (`mcp-use/oauth/storage`: Upstash, Redis, Postgres, Firestore, Cloudflare D1 or Durable Object, and an in-memory store for local development). `redisStorage` takes a connected client or a function that connects one on first use. Tools read the upstream token with `upstreamToken(ctx.auth)` or `ctx.auth.upstream`. When a sign-in or refresh fails, the server log names the cause without token or code values: the provider's own error code and description, the HTTP status and content type, an `iss` that names another issuer, or the network error. When a sign-in fails, the client's `error_description` names the provider's error code. The log also reports refused client metadata documents and stored records encrypted with a secret the server no longer has. Clients that signed in through the 1.x `oauthProxy` still send the provider's client ID and the bare server origin as the resource; while registration is on, the proxy accepts both, so those users approve the consent page once and sign in again without removing the server. Inside `mcp-use build`, where `isBuilding()` is true, `oauthProxy` requires no secret, store, or upstream client credentials, and `upstashStorage` requires no URL or token.

OAuth providers can now register public HTTP routes from `setup()` with `host.route()`, read the mount mode as `host.mode` and the `listen()` bind address as `host.listenHost`, and compute `oauthMetadata` from the resolved resource URL. OAuth endpoints under the MCP path are never written to trace logs, and `oauthEnvironmentValue` no longer throws on runtimes without `process`.
